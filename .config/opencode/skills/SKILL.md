# Агент MLDev-экспериментов

## Входные данные

Работай с:

1. текущим ML/Data Science репозиторием;
2. описанием эксперимента от пользователя.

## Правила

1. Используй только вычисления, которые уже существуют в репозитории.
2. Не придумывай ML-логику, статистические операции или преобразования данных.
3. Для каждой предлагаемой операции укажи конкретное доказательство:
   - путь к файлу в репозитории;
   - CLI-команду, функцию, класс или ячейку notebook;
   - известные входы и выходы.
4. Если доказательств недостаточно, пометь операцию как `unresolved`.
5. Не переходи к генерации или выполнению, пока хотя бы одна обязательная
   операция имеет статус `unresolved`.

## Исследование проекта

1. Изучи дерево репозитория.
2. Прочитай README, файлы настройки, точки входа, скрипты и notebooks.
3. Найди существующие операции получения и преобразования данных.
4. Извлеки требуемые гипотезы, метрики, пороги, входы и выходы.
5. Определи зависимости между операциями.
6. Свяжи каждую операцию с доказательством из репозитория.

Не анализируй виртуальные окружения, кэши, сгенерированные результаты и большие
наборы данных.

## Отчёт об исследовании

Укажи:

1. найденные операции в порядке зависимостей;
2. доказательство для каждой операции;
3. ожидаемые входы и выходы;
4. нерешённые требования и недостающие доказательства.

## Построение плана

После исследования создай в корне анализируемого репозитория файл
`mldev-agent-plan.json`.

1. Прочитай полную схему `schema/mldev-agent-plan-v1.schema.json` из каталога
   этого skill.
2. Запиши исходный запрос в `request`.
3. Добавь каждую проверяемую гипотезу в `hypotheses`.
4. Опиши входные, промежуточные и выходные файлы в `artifacts`.
5. Добавь все необходимые операции в `stages`, включая получение и подготовку
   данных.
6. Для каждой стадии укажи evidence, входы, выходы и зависимости.
7. Не дублируй общую операцию под разными идентификаторами.
8. Расположи все стадии в `pipeline.runs` в порядке выполнения.
9. Установи `pipeline.sequential` в `true`.
10. Запиши неподтверждённые операции в `unresolved`.

Значения `stage.inputs` и `stage.outputs` должны быть идентификаторами
артефактов. Значения `artifact.producer`, `artifact.consumers`,
`stage.depends_on` и `hypothesis.stage_id` должны быть идентификаторами стадий.

## Проверка плана

Запусти `helpers/validate_plan.py` из каталога этого skill:

```bash
python <каталог-skill>/helpers/validate_plan.py \
  mldev-agent-plan.json \
  --repository .
```

Исправляй план, пока валидатор не напечатает `VALID`.

Перед генерацией эксперимента повтори проверку с флагом
`--require-resolved`. Если проверка не прошла, остановись и сообщи пользователю
о нерешённых требованиях.

## Генерация MLDev

Переходи к генерации только после успешной проверки плана с флагом
`--require-resolved`.

1. Прочитай `references/mldev_patterns.md` из каталога этого skill.
2. Создай `.mldev/config.yaml` с модулями `base` и `jupyter`.
3. Создай `experiment.yml`.
4. Преобразуй стадии `basic-script` в `!BasicStage`.
5. Преобразуй стадии `jupyter` в `!JupyterStage`.
6. Используй YAML anchors, чтобы объявить каждую стадию один раз.
7. Создай один `!GenericPipeline` с именем `pipeline`.
8. Перенеси стадии в `pipeline.runs` без изменения порядка формального плана.
9. Для notebook используй `all_cells` только после проверки порядка и
   детерминированности всех code cells.

Не добавляй стадии, команды, параметры или пути, которых нет в валидированном
плане и evidence исходного репозитория.

После генерации проверь:

1. каждая стадия плана присутствует в `experiment.yml`;
2. порядок стадий совпадает с `mldev-agent-plan.json`;
3. общая подготовка данных объявлена один раз;
4. отсутствуют `!Stage` и `mldev_dvc`;
5. `!JupyterStage` не содержит неподтверждённых полей;
6. исходные файлы проекта не изменены.

На этом этапе не запускай pipeline и не создавай `runs/`.

## Версионирование данных

После генерации MLDev-конфигурации настрой DVC независимо от MLDev.

1. Прочитай `references/dvc_patterns.md` из каталога этого skill.
2. Инициализируй DVC в анализируемом Git-репозитории.
3. Добавь default remote `minio` с адресом `s3://dvc-storage`.
4. Настрой endpoint `http://localhost:9000`.
5. Получи и подготовь данные только существующими командами из evidence.
6. Добавь raw и prepared данные в DVC.
7. Отправь данные в remote командой `dvc push`.
8. Проверь `dvc status` и `dvc status --cloud`.

Версионируй только артефакты данных, указанные в формальном плане. Не добавляй
в DVC `runs/`, логи или виртуальное окружение.

Credentials должны приходить из `AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY` и `AWS_DEFAULT_REGION`. Не записывай их в файлы
репозитория, MLDev stages или сохранённые логи.

После настройки проверь:

1. существуют `.dvc/config`, `data/raw.csv.dvc` и
   `data/prepared.csv.dvc`;
2. `.dvc/config` не содержит credentials;
3. каждый DVC pointer содержит content hash;
4. локальная и remote-проверки завершились успешно.

При недоступности MinIO или ошибке авторизации остановись и сообщи об
инфраструктурной ошибке. Не изменяй эксперимент и не подменяй remote.

## Выполнение эксперимента

Перед запуском повторно проверь:

1. формальный план с флагом `--require-resolved`;
2. соответствие `experiment.yml` плану;
3. наличие `.mldev/config.yaml`;
4. наличие DVC pointers и доступность remote;
5. отсутствие credentials в созданных файлах.

Запускай pipeline только через `helpers/run_mldev.py` из каталога этого skill:

```bash
python <каталог-skill>/helpers/run_mldev.py \
  --repository . \
  --plan mldev-agent-plan.json \
  --experiment experiment.yml \
  --pipeline pipeline \
  --mldev-command venv/bin/mldev
```

Не запускай `mldev` отдельно в обход helper. Helper назначает единый `run_id`,
сохраняет stdout/stderr и независимо проверяет результат.

## Проверка результата

После выполнения открой напечатанный путь к `metadata.json`.

Считай эксперимент успешным, только если одновременно выполнены условия:

1. `status` равен `succeeded`;
2. список `errors` пуст;
3. каждая ожидаемая стадия оставила ровно один marker;
4. стадии выполнились в порядке формального плана;
5. все ожидаемые артефакты существуют;
6. каждый результат гипотезы содержит `accepted: true`;
7. `dvc status` и `dvc status --cloud` завершились успешно.

Не делай вывод об успехе только по exit code MLDev.

## Итоговый отчёт

Сообщи пользователю:

1. путь к `mldev-agent-plan.json`;
2. порядок стадий pipeline;
3. пути к `experiment.yml`, `.mldev/config.yaml` и DVC pointers;
4. `run_id` и путь к `metadata.json`;
5. результат каждой гипотезы;
6. итог локальной и remote-проверки DVC.

Отделяй подтверждённые результаты от нерешённых требований и ошибок.
